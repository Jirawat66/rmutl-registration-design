# 03 — Software Requirements Specification (SRS)

> SRS นี้เขียนขึ้นเพื่อกำหนดการออกแบบ **ต้นแบบ** แต่ละข้อจึงผูกกับหน้าจอใน Figma ตอนพัฒนาจริงให้ใช้เป็น baseline ของ requirement และดูส่วนที่ต้องเพิ่มเติมใน [09-backlog.md](09-backlog.md)

## Functional Requirements

| ID | Requirement | รายละเอียด | Use Case | Screen |
|---|---|---|---|---|
| FR-01 | บันทึกและแก้ไขประวัติส่วนตัว | แสดงข้อมูลประวัติและขั้นตอนการแก้ไขข้อมูลติดต่อ | UC-01 | SCR-01 |
| FR-02 | ตารางเรียน ตารางสอบ | แสดงตารางเรียนและตารางสอบประจำภาค ครบทั้งวัน เวลา ห้อง และผู้สอน | UC-02 | SCR-02 |
| FR-03 | ปฏิทินการศึกษา | แสดงวันสำคัญประจำปีการศึกษา เช่น วันเปิด-ปิดเทอม วันเพิ่ม-ถอน วันสอบ | UC-03 | SCR-03 |
| FR-04 | ค้นหารายวิชาที่เปิดสอน | ค้นหาด้วยรหัสหรือชื่อวิชา แสดงจำนวนที่นั่งคงเหลือ | UC-04 | SCR-04 |
| FR-05 | ลงทะเบียนเรียน | เลือกและยืนยันรายวิชา พร้อมเตือนเมื่อตารางเรียนซ้อนกัน | UC-05 | SCR-05 |
| FR-06 | ถอนรายวิชา | ยื่นคำร้องถอนพร้อมเหตุผล และแสดงสถานะการพิจารณา | UC-06 | SCR-06 |
| FR-07 | แสดงผลการลงทะเบียน | สรุปวิชาที่ลงสำเร็จ/ไม่สำเร็จ และหน่วยกิตรวมของเทอม | UC-07 | SCR-07 |
| FR-08 | แสดงผลการเรียน | แสดงผลการเรียน GPA และ GPAX แยกตามภาคเรียน | UC-08 | SCR-08 |
| FR-09 | ยื่นขอสำเร็จการศึกษา | ยื่นคำร้องขอจบ พร้อมเช็กลิสต์ความครบของหลักสูตร และติดตามสถานะ | UC-09 | SCR-09 |
| FR-10 | สถานะการชำระเงินและหนี้สิน | แสดงยอดค้างชำระ สถานะ และวันครบกำหนด | UC-10 | SCR-10 |

## Non-Functional Requirements

| ID | หัวข้อ | รายละเอียด | วิธีตรวจ |
|---|---|---|---|
| NFR-01 | Usability | เข้าถึงเมนูหลักได้ภายใน 3 ครั้งการแตะ | นับจำนวนการแตะจาก Home ไปแต่ละฟังก์ชัน |
| NFR-02 | Consistency | สี ไอคอน และฟอนต์มาจากระบบเดียวกันทั้งแอป (Design System) ตามอัตลักษณ์มหาวิทยาลัย | ใช้เฉพาะค่าใน `design/tokens` |
| NFR-03 | Mobility | แสดงผลถูกต้องทั้ง iOS และ Android | ทดสอบบนอุปกรณ์ทั้ง 2 ระบบ |

## User Stories & Acceptance Criteria

| ID | User Story | Acceptance Criteria (Given / When / Then) |
|---|---|---|
| US-01 | ในฐานะนักศึกษา ฉันต้องการดูและแก้ไขประวัติส่วนตัว เพื่อให้ข้อมูลติดต่อเป็นปัจจุบันเสมอ | **Given** อยู่หน้าประวัติส่วนตัว **When** แก้ไขเบอร์โทรศัพท์และกดบันทึก **Then** แสดงหน้าต่างยืนยันการบันทึกข้อมูล |
| US-02 | ในฐานะนักศึกษา ฉันต้องการดูตารางเรียนและตารางสอบ เพื่อไปเรียนและสอบได้ถูกวัน เวลา และห้อง | **Given** อยู่หน้าตารางเรียน **When** เปิดหน้า **Then** แสดงวัน เวลา ห้องเรียน และผู้สอนของทุกวิชาที่ลงทะเบียน |
| US-03 | ในฐานะนักศึกษา ฉันต้องการดูปฏิทินการศึกษาประจำปี เพื่อวางแผนล่วงหน้า | **Given** อยู่หน้าปฏิทินการศึกษา **When** เปิดหน้า **Then** แสดงวันสำคัญ เช่น วันเปิด-ปิดเทอม และวันสอบครบถ้วน |
| US-04 | ในฐานะนักศึกษา ฉันต้องการค้นหารายวิชาที่เปิดสอน เพื่อรู้ว่ามีวิชาอะไรและยังมีที่นั่งไหม | **Given** อยู่หน้าค้นหารายวิชา **When** กรอกรหัสหรือชื่อวิชา **Then** แสดงวิชาที่ตรงกับคำค้นพร้อมจำนวนที่นั่งคงเหลือ |
| US-05 | ในฐานะนักศึกษา ฉันต้องการลงทะเบียนได้ครบตามแผนโดยไม่ผิดเงื่อนไข | **Given** อยู่หน้าเลือกรายวิชา **When** เลือกวิชาที่เวลาทับซ้อนแล้วกดยืนยัน **Then** แสดงข้อความเตือนตารางเรียนซ้อนกัน |
| US-06 | ในฐานะนักศึกษา ฉันต้องการยื่นคำร้องถอนรายวิชาพร้อมเหตุผล เพื่อจัดการภาระการเรียน | **Given** อยู่หน้าถอนรายวิชา **When** ระบุเหตุผลและยืนยันคำร้อง **Then** สถานะวิชาเปลี่ยนเป็น "รอการพิจารณา" |
| US-07 | ในฐานะนักศึกษา ฉันต้องการตรวจสอบผลการลงทะเบียนหลังยืนยัน เพื่อมั่นใจว่าบันทึกครบ | **Given** อยู่หน้าผลการลงทะเบียน **When** เปิดหน้าหลังยืนยัน **Then** แสดงวิชาที่สำเร็จและไม่สำเร็จแยกกันชัดเจน |
| US-08 | ในฐานะนักศึกษา ฉันต้องการตรวจสอบผลการเรียนและเกรดเฉลี่ยสะสม เพื่อติดตามความก้าวหน้า | **Given** อยู่หน้าผลการเรียน **When** เลือกภาคเรียน **Then** แสดงเกรดรายวิชาและ GPA/GPAX ของภาคนั้น |
| US-09 | ในฐานะนักศึกษา ฉันต้องการยื่นคำร้องขอสำเร็จการศึกษา เพื่อดำเนินเรื่องจบได้ครบตามขั้นตอน | **Given** อยู่หน้ายื่นขอสำเร็จการศึกษา **When** หน่วยกิตและเกรดเฉลี่ยผ่านเกณฑ์ **Then** ปุ่มยื่นคำร้องอยู่ในสถานะเปิดใช้งาน (ไม่ผ่านเกณฑ์ = ปุ่ม disabled) |
| US-10 | ในฐานะนักศึกษา ฉันต้องการตรวจสอบสถานะการชำระเงิน เพื่อรู้ยอดค้างชำระและวางแผนการเงิน | **Given** อยู่หน้าสถานะการชำระเงิน **When** เปิดหน้า **Then** แสดงยอดค้างชำระและวันครบกำหนดชัดเจน |

## Priority

จัดลำดับจากความถี่และความรุนแรงของ Pain Point ใน Journey Map ของทั้ง 2 กลุ่มผู้ใช้ **แนะนำให้พัฒนาและทดสอบตามลำดับนี้**

| Priority | FR | ฟังก์ชัน | เหตุผล |
|---|---|---|---|
| 🔴 Highest | FR-05 | ลงทะเบียนเรียน | กระทบทั้งนักศึกษาและเจ้าหน้าที่มากที่สุด จำนวนที่นั่งไม่ตรงข้อมูลจริง และมีผู้ใช้พร้อมกันจำนวนมาก |
| 🔴 Highest | FR-06 | ถอนรายวิชา | ขั้นตอนอนุมัติเป็นคอขวด ต้องทำสถานะคำร้องให้ชัดเจน |
| 🟠 High | FR-10 | สถานะการชำระเงิน | Pain point ร่วมเรื่องติดตามสถานะและช่องทางชำระ |
| 🟡 Medium | FR-01, FR-09 | แก้ไขประวัติ / ขอสำเร็จการศึกษา | มีขั้นตอนอนุมัติ แต่ปัญหาเกิดน้อยกว่า |
| 🟢 Normal | FR-02, 03, 04, 07, 08 | ตาราง / ปฏิทิน / ค้นหา / ผลลงทะเบียน / ผลการเรียน | แสดงผลอย่างเดียว (Read-only) ไม่มีขั้นตอนอนุมัติ |

ฟังก์ชันกลุ่ม Highest ต้องมี error prevention และการยืนยันหลายขั้นตอน

## Feature Concepts

| ด้านปัญหา | Feature Concept | ที่มาจาก Pain Point |
|---|---|---|
| โครงสร้างและการนำทาง | **Dashboard หน้าแรก:** ตารางเรียนวันนี้, ปุ่มลัดลงทะเบียน, กำหนดการสำคัญ | "เมนูซับซ้อน หากำหนดการไม่เจอ" |
| การกรอกข้อมูล | **ฟอร์มแยกสิทธิ์ 2 ระดับ:** แก้ได้ทันที / ต้องแนบเอกสารรออนุมัติ พร้อม validate ก่อนบันทึก | "ไม่แน่ใจว่าแก้ข้อมูลได้เองแค่ไหน" |
| ส่วนติดต่อผู้ใช้ | **Mobile-First:** ปุ่มขนาดใหญ่ รวมข้อมูลที่ต้องตรวจไว้ในหน้าเดียว | "ปุ่มกดยาก ต้องสลับหน้าจอตรวจหลายจุด" |
| ความโปร่งใส | **Status Stepper:** รออาจารย์อนุมัติ → รอเจ้าหน้าที่ยืนยัน → สำเร็จ | "ไม่รู้สถานะคำร้องถอน / ค่าธรรมเนียม" |

แสดงสถานะแบบ On-demand ในหน้าจอ ไม่ได้ออกแบบ push notification
